# Audio Playground — XM6 Edition

> **Public downloads & release info:** [main branch](https://github.com/JerryKoller/Kill-Chain) · This `app` branch is the source code.

> A futuristic sound laboratory for shaping music until your **Sony WH-1000XM6** feel magical.

This is a Windows desktop app (Electron + React + TypeScript + Web Audio + WebGL2) built around three ideas:

1. **Exploration over engineering.** Drag glowing nodes, fling sliders, hold "A" / "B" to compare — never look at a spreadsheet.
2. **Headphone-aware DSP.** A purpose-built correction profile sits beneath your tweaks so every change starts from a flat, honest XM6.
3. **Instant feedback.** Sub-frame UI, smooth 60 fps GPU visualizer, and a DSP chain wired for low latency.

---

## Quick start

```bash
cd audio-playground
npm install
npm run dev          # browser preview (no Electron)
npm run dev:electron # full Windows desktop shell with hot reload
npm run package      # build the Windows installer (NSIS)
```

Requires **Node 18+** and **npm 9+**. The first time you run, click anywhere in the window — `AudioContext` requires a user gesture before it can produce sound.

## Install on Windows

### Step 1 (only if the project is currently on OneDrive): move it to the local hard drive

Double-click **`scripts\Move To Local Drive.bat`** once.

It will:

1. Copy the project from OneDrive to `C:\Users\<you>\Audio-Playground\` (skipping `node_modules` and build caches).
2. Automatically run the shortcut installer from the new local location, so the Desktop icon points at the local launcher (not OneDrive).
3. Leave the OneDrive copy in place. You can delete it manually after you've confirmed the new copy works, or re-run with `-RemoveSource` to delete it now.

Pass `-Destination "C:\Some\Other\Path"` to choose a different local folder. The script refuses any destination containing `OneDrive`.

### Step 2: install the Desktop icon

(Already done by Step 1. Skip this if you ran the migration above.)

Otherwise, double-click **`scripts\Install Desktop Shortcut.bat`** once.

It will:

1. Draw a custom cyberpunk neon icon procedurally with GDI+ (`assets/icon.png`).
2. Bake a multi-resolution `.ico` (16 → 256 px) with PNG sub-images.
3. Drop **`Audio Playground.lnk`** on your Desktop, pointing at the launcher script with the new icon.

Double-click the icon to start the app. The first launch will:

1. Auto-detect Node.js, including installs that aren't on `PATH` (checks `Program Files`, `LOCALAPPDATA`, `nvm-windows`, `fnm`).
2. If Node.js is missing, offer to install **Node.js LTS** via `winget` (a Windows UAC prompt will appear — accept it).
3. Run `npm install` + `npm run build` (~1 minute).

Every launch after that opens the desktop window almost instantly. If `winget` isn't available, the launcher opens https://nodejs.org/ in your browser and asks you to install LTS manually, then re-run the shortcut.

| File | Purpose |
| --- | --- |
| `scripts/Move To Local Drive.bat`      | One-time migration off OneDrive. Copies the project to `C:\Users\<you>\Audio-Playground\` and re-installs the shortcut. |
| `scripts/Move-To-Local-Drive.ps1`      | PowerShell implementation of the migration. Accepts `-Destination` and `-RemoveSource`. |
| `scripts/Install Desktop Shortcut.bat` | One-time installer (double-click). |
| `scripts/Install-Desktop-Shortcut.ps1` | Does the actual work: draws icon, writes `.lnk` to the visible Desktop AND `%USERPROFILE%\Desktop` (so it survives if you later turn off OneDrive Desktop backup). Pass `-Force` to redraw the icon. |
| `scripts/Launch Audio Playground.bat`  | The launcher the shortcut points at. Handles first-time install + build, then runs Electron in production mode. |
| `scripts/_launch_electron.vbs`         | Helper that spawns Electron silently so the launcher console can close immediately. |
| `assets/icon.png` / `assets/icon.ico`  | Generated by the installer. |

### Troubleshooting: shortcut runs the installer, then nothing happens

This was a real bug, now fixed. Cause: the root `package.json` declares `"type": "module"` (required by Vite). But the Electron main/preload sources are compiled by `tsc` with `"module": "CommonJS"` and emit `require(...)`, `__dirname`, `module.exports`. Node then refused to run `dist-electron/main.js` as ESM and Electron's main process crashed on startup; the silent VBS launcher swallowed the error so you saw nothing at all.

Fix: the `build` script now runs `scripts/finalize-electron-build.mjs`, which drops a tiny `dist-electron/package.json` with `{"type": "commonjs"}` so Node treats that subtree as CommonJS. The regular launcher also self-heals this marker file if it's missing, so older builds work after upgrading without a rebuild.

If you ever see "I click the icon, it runs setup, nothing pops up" again, run **`scripts\Launch Audio Playground (Debug).bat`** instead. It runs Electron in the foreground with stderr visible and keeps the console open after exit so you can read the error.

### Why didn't the shortcut appear the first time?

If Windows backs up your Desktop to OneDrive, `[Environment]::GetFolderPath("Desktop")` returns the **OneDrive Desktop folder** (e.g. `C:\Users\<you>\OneDrive\Desktop`), which *is* what you see on screen — but the previous installer only printed a generic success message, so it wasn't obvious whether the `.lnk` was actually written. The hardened installer now:

- Prints the full target path and file size for every shortcut it writes.
- Writes the `.lnk` to **both** the OS-reported Desktop and `%USERPROFILE%\Desktop` (if those differ), so the icon survives if you ever disable OneDrive backup.
- Calls `SHChangeNotify(SHCNE_ASSOCCHANGED)` to force the shell to refresh icons.
- Fails loudly (non-zero exit code) if no shortcut got written.

> The installer never touches anything outside `assets/` and your Desktop folder. Re-run it any time with `-Force` to refresh the icon, or move the project — just re-run the installer afterward to repoint the shortcut.

## Audio engine

`src/audio/AudioEngine.ts` constructs a single graph:

```
 source → input → correctionEQ ──► friendlyEQ ──► harmonicEnhancer
                                                        │
                                                        ▼
                       saturator ──► transientShaper ──► glueComp
                                                        │
                                                        ▼
                        spatialEnhancer ──► stereoWidener ──► reverb
                                                        │
                                                        ▼
                       analyserPost ──► outputGain ──► limiter ──► destination
                                                        ▲
                                                analyserPre (pre-DSP tap for A/B)
```

### DSP modules

| Module               | File                                          | What it does                                                                  |
| -------------------- | --------------------------------------------- | ----------------------------------------------------------------------------- |
| `ParametricEQ`       | `src/audio/dsp/ParametricEQ.ts`               | Editable chain of `BiquadFilterNode`s, plus magnitude-response computation.   |
| `HarmonicEnhancer`   | `src/audio/dsp/HarmonicEnhancer.ts`           | Highpass → WaveShaper sidechain summed with the dry signal for "alive" tone. |
| `Saturator`          | `src/audio/dsp/Saturator.ts`                  | Soft-clipped tanh curve with auto-gain compensation.                          |
| `TransientShaper`    | `src/audio/dsp/TransientShaper.ts`            | Fast/slow compressor pair → modulates attack vs sustain.                      |
| `StereoWidener`      | `src/audio/dsp/StereoWidener.ts`              | True Mid/Side widening with native node math.                                 |
| `SpatialEnhancer`    | `src/audio/dsp/SpatialEnhancer.ts`            | Crossfeed + Haas delay for an out-of-head feeling on closed-backs.            |
| `Reverb`             | `src/audio/dsp/Reverb.ts`                     | Convolution reverb with procedurally baked, size-morphing impulses.           |
| `DynamicsCompressor` | native node                                   | "Glue" compression / brick-wall limiter.                                       |

### The XM6 correction profile

`src/audio/xm6Profile.ts` ships a 8-band correction EQ tailored to the WH-1000XM6's stock tuning:

- Slight sub-rumble shelf at 28 Hz
- Mid-bass tame around 110 Hz
- De-mud notch at 420 Hz
- **+2.4 dB presence at 2.8 kHz** (counters the XM6 dip)
- Edge polish at 5.2 kHz
- Air bumps at 9 kHz and 14 kHz to wake up the top end

These are starting points — the **Guided Calibration** personalizes them per user.

### Friendly slider mapping

The user never sees "+3.4 dB @ 2.83 kHz, Q 1.1". They see knobs labeled **Warmth, Vocals, Clarity, Air, Sparkle, Punch, Texture, Glue, Width, Holographic, Space, Room, Harmonics, Saturation**. Each one drives one or many DSP nodes — `AudioEngine.applyParams()` is the single, cheap entry point invoked on every drag.

### Safety / gain staging

- `outputGain` defaults to **−2.5 dB** to leave headroom for the enhancer/saturator stages.
- A brick-wall `DynamicsCompressor` (ratio 20, threshold −1.5 dB, attack 0.5 ms) sits between `outputGain` and `destination`. You can't blow up the drivers no matter how hard you push.

## State management

| Store                | File                                       | Owns                                                                 |
| -------------------- | ------------------------------------------ | -------------------------------------------------------------------- |
| `useAudioStore`      | `src/state/audioStore.ts`                  | Sound params, correction bands, undo/redo history, A/B snapshot.     |
| `usePlayerStore`     | `src/state/playerStore.ts`                 | `HTMLAudioElement`, playback, volume, loop, file metadata.           |
| `useCalibrationStore`| `src/state/calibrationStore.ts`            | Adaptive A/B engine wrapper.                                          |
| `useUIStore`         | `src/state/uiStore.ts`                     | Current view, toast notifications.                                    |

All param updates go through `useAudioStore.setParam(s)` → the store records a history entry, then calls `AudioEngine.applyParams()` which only touches the affected nodes. That's the secret to the sub-frame feedback even while dragging.

## Visualization pipeline

`src/components/Visualizer/VisualizerGL.ts`

1. Each frame, read frequency + time-domain bytes from `AudioEngine.analyserPost`.
2. Upload them as two 1×N `R8` textures.
3. Render a fullscreen triangle strip through a single fragment shader that composites:
   - Reactive neon rings (radius pumps with bass/mid/high band energies)
   - 96 spectral particles arranged on a circle, radius modulated by `texture(uFreq, …)`
   - A glowing vector waveform line from the time-domain texture
   - HSV background gradient where hue + warmth + spread come from the **current SoundParams** — so the visualizer's personality literally morphs with your tuning.
4. CPU-side fallback to a 2D bar+wave renderer if WebGL2 isn't available.

Target: 60 fps; degrades gracefully on low-end GPUs because there's no vertex traffic.

## The Guided Calibration engine

`src/lib/adaptiveEngine.ts` implements a tiny adaptive A/B trainer:

- 14 axes (subBass, bass, warmth, vocals, clarity, air, sparkle, punch, texture, compression, width, spatial, harmonics, saturation).
- Each step:
  1. **Pick** an axis weighted by `1 − |confidence|` (prefer uncertain axes), penalised if the axis was probed recently.
  2. **Probe magnitude** decays cosinusoidally from 0.45 → 0.08 — explore early, refine late.
  3. Present **variant A** = current profile + probe, **variant B** = current − probe.
  4. On user pick, move the profile 70 % of the probe in that direction and bump confidence.
- After ~30 questions the user lands on a personalized `SoundParams` they can apply, tweak, or reset.

The radar chart in the right panel shows the **converged profile** (magenta) overlaid on the **live preview** (cyan) so the user can watch their signature emerge.

## Adaptive A/B engine — ideas to push further

1. **Confidence-bounded BO.** Replace the heuristic axis-picker with a tiny Gaussian-Process bandit (only 14 axes → trivial).
2. **Pairwise contrastive probes.** Instead of always varying one axis, occasionally probe two correlated axes (e.g. warmth + bass) to capture interaction effects.
3. **Genre-conditioned questions.** Detect the playing track's genre via spectral features and bias the probe magnitudes (e.g. larger sub-bass probes for electronic genres).
4. **Time-of-day signatures.** Track the user's choices by hour and learn separate "late-night vs morning" profiles, then auto-blend at runtime.
5. **Forced-choice tie-breaker.** When the user hesitates (>2 s between previews), drop the probe magnitude — they're hearing a subtle effect and a smaller answer is more reliable.
